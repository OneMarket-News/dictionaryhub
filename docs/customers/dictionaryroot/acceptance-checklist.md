# DictionaryRoot Customer Acceptance Checklist

## Brand foundation

- [ ] Browser titles use DictionaryRoot.
- [ ] Shared DictionaryRoot navigation appears on public V2 pages.
- [ ] DictionaryRoot mark and tagline appear.
- [ ] “Powered by SourceRoot” appears without making the page feel administrative.
- [ ] SourceRoot administrative pages retain SourceRoot branding.

## Connection

- [ ] Customer manifest loads.
- [ ] SourceRoot health check passes.
- [ ] Stable DictionaryRoot bundle is found.
- [ ] Node, assertion, and edge counts load.
- [ ] Search for `knowledge` returns DictionaryRoot records.

## Search and meaning selection

- [ ] Visitors can search a written term.
- [ ] Multiple word senses are distinguishable.
- [ ] Parts of speech and concise definitions appear in results.
- [ ] Unknown terms have a useful empty state.

## Concept experience

- [ ] Node identity loads.
- [ ] Definitions and examples load from assertions.
- [ ] Relationships load from edges.
- [ ] Source attribution is visible.
- [ ] Internal IDs are secondary or placed under advanced details.

## Knowledge graph

- [ ] A selected concept becomes the center node.
- [ ] Immediate neighbors load from the SourceRoot API.
- [ ] Relationship labels are customer-friendly.
- [ ] Clicking a neighbor can expand it.
- [ ] Duplicate nodes and edges are prevented.
- [ ] Graph limits protect browser performance.
- [ ] Reset and back controls work.

## Experience quality

- [ ] Loading states explain what is happening.
- [ ] Empty states suggest a useful next action.
- [ ] Error states preserve trust and offer retry/status actions.
- [ ] Keyboard focus is visible.
- [ ] Main navigation is keyboard accessible.
- [ ] Narrow-screen layout remains usable.
- [ ] Reduced-motion preferences are respected.

## Update workflow

- [ ] Replacement bundle validates.
- [ ] Stable bundle replacement imports successfully.
- [ ] Diagnostic checks pass after replacement.
- [ ] DictionaryRoot shows updated data without frontend code changes.
