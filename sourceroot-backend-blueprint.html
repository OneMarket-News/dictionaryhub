Recommended Alpha Architecture

Start with one API service and one PostgreSQL database. Keep SourceRoot's existing JSON contract at the API boundary, then normalize core graph objects into relational tables while preserving full original JSON and extension payloads.

Frontend

Existing HTML/JavaScript pages using a repository adapter.

API

Node.js + TypeScript REST service.

Database

PostgreSQL with JSONB for extensions and original artifacts.

Authentication

Managed identity provider or secure session-based auth.

Deployment

One API deployment, one managed Postgres instance, static frontend hosting.

Planning decision: do not begin with microservices, blockchain storage, a graph database, or multiple databases. The current workload is small and relational integrity matters more than horizontal scale.

Architecture Decisions

DecisionRecommendationReason
API styleREST firstMaps directly to current lifecycle operations and is easier to test than introducing GraphQL immediately.
Backend languageTypeScriptMatches the browser JavaScript model while adding types and safer schema contracts.
DatabasePostgreSQLStrong foreign keys, transactions, JSONB, full-text search, and mature hosting.
Graph storageRelational edge tableThe graph is still modest. A dedicated graph database would add complexity without current benefit.
ArtifactsStore exact JSON plus normalized rowsPreserves portability and auditability while enabling search and joins.
ValidationShared rules, server executionThe server must become the authority while the browser remains a fast preview.
Audit historyAppend-only lifecycle eventsMatches the browser model and protects provenance.
Hub extensionsJSONB firstHistoryRoot and future hubs can evolve before dedicated extension tables are stable.

Service Boundaries

Validation Service

Schema checks, controlled vocabularies, references, counts, readiness, and hashes.

Bundle Service

Bundle creation, version conflicts, retrieval, indexing, and staging.

Package Service

Package creation, exact artifact storage, integrity verification, and restore rules.

Inspection Service

Reviewer decisions, issues, hashes, and approval history.

Lifecycle Event Service

Append-only event writes and searchable audit history.

Knowledge Query Service

Node search, assertions, relationships, sources, and cross-hub lookups.

These are code-level modules inside one application at first—not separately deployed services.

Database Model

The included SQL blueprint defines users, roles, bundles, nodes, assertions, edges, sources, source links, revisions, snapshots, packages, inspections, lifecycle events, and hub extensions.

Core graph

nodes, assertions, edges, sources

Lifecycle

bundle_snapshots, packages, package_inspections, lifecycle_events

Identity

users, roles, user_roles

Extensibility

hub_extensions with JSONB payloads

Every uploaded bundle and package should preserve its original JSON, even after its objects are normalized into relational rows.

API Contract

The included OpenAPI file defines the first public contract. The most important endpoints are:

POST /api/v1/validate
POST /api/v1/bundles
GET  /api/v1/bundles/:bundleId
POST /api/v1/bundles/:bundleId/validate
POST /api/v1/bundles/:bundleId/stage
POST /api/v1/packages
POST /api/v1/packages/:packageId/verify
POST /api/v1/packages/:packageId/inspections
POST /api/v1/packages/:packageId/restore
GET  /api/v1/nodes/:nodeId
GET  /api/v1/events
The first implemented endpoint should be POST /validate. It provides immediate value without requiring authentication, migration, or persistence.

Authentication and Authorization

RoleCapabilities
ReaderRead approved public nodes, assertions, sources, and packages.
CreatorCreate bundles, submit validation, and stage owned bundles.
ReviewerInspect packages and save approval or rejection decisions.
AdminManage users, roles, revocations, migrations, and all records.

Do not invent a custom password system unless necessary. Use a managed identity provider or a proven authentication library and store only the minimum identity metadata SourceRoot needs.

Migration Phases

0. Freeze contract

Tests, fixtures, schema reference, package version.

1. Read-only mirror

Health, validation, bundle reads, node reads.

2. Bundle persistence

Store bundles, graph objects, snapshots, and events.

3. Package persistence

Export, verify, inspect, and restore through API.

4. Identity

Users, roles, creators, reviewers, permissions.

5. Frontend cutover

Repository adapter switches pages from localStorage to API.

6. Hardening

Backups, signatures, revocation, rate limits, monitoring.

Key Risks

Validator drift

Browser and server produce different outcomes. Prevent with shared fixtures and contract tests.

Premature normalization

Hub schemas change before tables stabilize. Preserve full JSON and use JSONB extensions.

Identity overclaim

A reviewer name is not cryptographic proof. Treat signatures as a later security layer.

Audit mutation

Editing historical events would weaken provenance. Use append-only event writes.

Scope expansion

Search, payments, tokens, and public publishing can wait until persistence works.
