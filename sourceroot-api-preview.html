SourceRoot API Preview

A prototype view of how SourceRoot could expose import validation, nodes, assertions, assertion credibility, edges, relationship credibility, sources, search, citations, and revisions through an API layer. This is not a live backend yet. It is the product contract for what the engine is becoming.

API Purpose

SourceRoot’s API would let apps, AI systems, search tools, partner companies, and future hubs validate import bundles and retrieve structured knowledge with provenance, claim-level trust context, and relationship-level trust context. The key idea is simple: every answer should be traceable back to nodes, assertions, assertion credibility, relationships, relationship credibility, sources, and revisions.

Application / AI / Partner Tool ↓ SourceRoot API ↓ Import Validation → Search → Nodes → Assertions → Assertion Credibility → Edges → Relationship Credibility → Sources → Citations ↓ Verified, inspectable, source-aware knowledge

Core Endpoints

How an AI Would Use SourceRoot

1. Validate Import Bundle Before new data enters SourceRoot, the import validator checks the bundle using engine/importValidator.js. Broken data is blocked; reviewable data is marked ready with warnings.
2. Identify Query The AI detects the user is asking about a concept, source, relationship, or claim.
3. Search Nodes It searches SourceRoot for matching nodes across DictionaryHub, BibleRoot, Wiki, and future hubs.
4. Retrieve Assertions It pulls definitions, statements, explanations, examples, and symbolic meanings.
5. Check Assertion Credibility It reviews credibility tier, confidence, verification status, support level, and interpretation level before treating a claim as reliable.
6. Follow Edges It follows relationships to related concepts, supporting nodes, opposing views, or cross-domain meanings.
7. Check Relationship Credibility It reviews whether the connection is direct, derived, inferred, symbolic, contextual, disputed, or needs review before using it in an answer.
8. Check Sources It verifies which sources support each assertion or relationship and whether those sources have license, publisher, review, and credibility metadata.
9. Cite and Log It cites the source-backed assertion or relationship and can log a citation event for credit, audit, or payment.

Import Validation Rule

SourceRoot should not import new knowledge until the bundle has passed validation. The validator must return a readiness status before imported nodes, assertions, edges, sources, or revisions are trusted by the system.

Import Bundle ↓ engine/importValidator.js ↓ Validation Result ↓ Ready / Ready With Warnings / Blocked

Assertion Credibility Rule

SourceRoot should never treat every assertion as equally reliable. The API must expose how each claim is supported. A source can be credible while a specific claim built from that source may still be direct, derived, inferred, interpretive, disputed, or prototype-only.

High-quality source + direct support = high assertion credibility High-quality source + loose interpretation = medium assertion credibility Prototype note + no external review = prototype or needs-review Community-maintained source + direct statement = medium assertion credibility Disputed source support = disputed assertion credibility

Relationship Credibility Rule

SourceRoot should not treat every edge as equally reliable. A relationship is also a claim. The API must show whether a connection between two nodes is direct, derived, inferred, symbolic, contextual, disputed, unsupported, or prototype-only.

Direct source-backed relationship = high relationship credibility Shared term with different context = medium relationship credibility Symbolic or theological relationship = interpretive relationship credibility Cross-hub relationship without review = needs-review Loose metaphorical connection = contextual or weak relationship credibility Disputed connection = disputed relationship credibility
