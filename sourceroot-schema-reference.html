Current Contract

SourceRoot currently uses a browser-based JSON contract. The core knowledge graph is made of nodes, assertions, edges, sources, and revisions. Bundles move through validation, staging, hashing, package export, inspection, restoration, and embedded revalidation.

Node Schema

A node represents a distinct concept, entity, event, person, place, institution, period, narrative, word, or other addressable knowledge object.

Field Type Requirement Meaning Validation
idstringRequiredStable unique identifier.Non-empty and unique among nodes.
titlestringRequiredPrimary display label.Non-empty.
typestringRequiredDomain-neutral or hub-specific node category.Non-empty; currently open vocabulary.
domainstringRequiredOwning or originating knowledge domain.Non-empty.
summarystringRecommendedShort human-readable description.Missing text may produce a warning.
sourceIdsstring[]RecommendedSources directly supporting the node record.Every ID must exist in sources.
statusstringOptionalLifecycle or domain state.Currently hub-defined.
metadataobjectOptionalHub-specific attributes preserved without altering the core node contract.Must be JSON-compatible.
Example node 
{
  "id": "event-great-chicago-fire",
  "title": "Great Chicago Fire",
  "type": "event",
  "domain": "HistoryRoot",
  "summary": "A major urban fire that spread across Chicago in October 1871.",
  "sourceIds": [
    "source-loc-guide",
    "source-encyclopedia-fire"
  ],
  "status": "historical",
  "metadata": {
    "startDate": "1871-10-08",
    "endDate": "1871-10-10"
  }
}

Assertion Schema

An assertion stores a claim about one node. Claims remain separate from nodes so evidence, confidence, interpretation, disagreement, and revision can be inspected independently.

Field Type Requirement Meaning Validation
idstringRequiredUnique assertion identifier.Non-empty and unique among assertions.
nodeIdstringRequiredNode this claim describes.Must reference nodes.id.
assertionTypestringRequiredCategory such as definition, date-range, cause, impact, or interpretation.Non-empty; open vocabulary.
labelstringRecommendedReadable assertion heading.Missing label may warn.
summarystringRecommendedShort claim text.At least one meaningful claim field should be present.
bodystringRecommendedFull claim text.Empty claims may warn or block later production validation.
domainstringRequiredKnowledge domain that produced the assertion.Non-empty.
sourceIdsstring[]Required for source-backed claimsEvidence supporting the claim.Every ID must reference sources.id.
credibilityTierenumRecommendedGeneral credibility classification.Must use controlled vocabulary.
confidenceenumRecommendedConfidence in this claim.Must use controlled vocabulary.
verificationStatusenumRecommendedHow the claim has been checked.Must use controlled vocabulary.
reviewStatusenumRecommendedHuman or workflow review state.Must use controlled vocabulary.
supportLevelenumRecommendedHow directly the evidence supports the assertion.Uses assertion support vocabulary.
interpretationLevelenumRecommendedDegree of interpretive judgment.Must use controlled vocabulary.
Example assertion 
{
  "id": "assertion-fire-dates",
  "nodeId": "event-great-chicago-fire",
  "assertionType": "date-range",
  "label": "Fire dates",
  "summary": "The fire burned from October 8 through October 10, 1871.",
  "body": "The Great Chicago Fire burned from the evening of October 8 through October 10, 1871.",
  "domain": "HistoryRoot",
  "sourceIds": [
    "source-loc-guide",
    "source-loc-map-blog"
  ],
  "credibilityTier": "high",
  "confidence": "strong",
  "verificationStatus": "source-backed",
  "reviewStatus": "reviewed",
  "supportLevel": "direct",
  "interpretationLevel": "low"
}

toNodeIdstringRequiredRelationship destination.Must reference nodes.id.
relationshipTypestringRequiredMachine-readable relationship category.Non-empty; currently open vocabulary.
labelstringRecommendedHuman-readable relationship phrase.Missing label may warn.
summarystringRecommendedReadable explanation of the connection.Missing summary may warn.
domainstringRequiredOriginating knowledge domain.Non-empty.
sourceIdsstring[]RecommendedSources supporting the relationship.Every ID must reference sources.id.
credibilityTierenumRecommendedGeneral credibility level.Controlled vocabulary.
confidenceenumRecommendedConfidence in the connection.Controlled vocabulary.
verificationStatusenumRecommendedVerification state.Controlled vocabulary.
reviewStatusenumRecommendedHuman review state.Controlled vocabulary.
supportLevelenumRecommendedHow directly evidence supports the relationship.Uses relationship support vocabulary.
relationshipStrengthenumRecommendedStructural importance or strength.Controlled vocabulary.
interpretationLevelenumRecommendedDegree of interpretation in making the connection.Controlled vocabulary.

    "source-loc-guide"

Source Schema

A source describes where evidence came from. Source credibility and licensing are tracked separately from the truth or strength of any specific assertion.

Field Type Requirement Meaning Validation
idstringRequiredUnique source identifier.Non-empty and unique among sources.
namestringRequiredSource title or display name.Non-empty.
typestringRequiredSource category.Non-empty; open vocabulary.
domainstringRequiredKnowledge domain using the source.Non-empty.
publisherstringRecommendedPublishing organization or authoring body.Missing publisher may warn.
urlstringRecommendedExternal or internal source location.Should be a usable URL when present.
sourceClassstringOptionalAdditional source classification.Open vocabulary.
qualityTierenum-like stringOptionalQuality label, generally aligned with credibility tier.Should not contradict credibility metadata.
credibilityTierenumRecommendedInstitutional or evidentiary credibility classification.Controlled vocabulary.
verificationStatusenumRecommendedHow the source record has been checked.Controlled vocabulary.
reviewStatusenumRecommendedReview state.Controlled vocabulary.
licensestringRecommendedHuman-readable use conditions.Missing license may warn.
licenseStatusstringRecommendedOperational license classification.Internal-only or unclear values may warn.
lastRevieweddate stringRecommendedMost recent review date.Prefer ISO 8601 date.
notesstringOptionalAdditional provenance or usage notes.Free text.
Example source 
{
  "id": "source-loc-guide",
  "name": "Great Chicago Fire of 1871: Topics in Chronicling America",
  "type": "archive-guide",
  "domain": "HistoryRoot",
  "publisher": "Library of Congress",
  "url": "https://guides.loc.gov/chronicling-america-great-chicago-fire",
  "sourceClass": "archive-guide",
  "qualityTier": "very-high",
  "credibilityTier": "very-high",
  "verificationStatus": "reviewed",
  "reviewStatus": "reviewed",
  "license": "External source; follow publisher terms",
  "licenseStatus": "linked-reference-only",
  "lastReviewed": "2026-07-16"
}

Revision Schema

A revision records that a knowledge object changed, was reclassified, corrected, deprecated, or received a new interpretation.

Field Type Requirement Meaning Validation
revisionIdstringRequiredUnique revision identifier.Non-empty and unique among revisions.
objectIdstringRequiredObject affected by the revision.Should reference a known core or extension object.
objectTypestringRequiredType of revised object.Non-empty.
revisionTypestringRequiredNature of the change.Open vocabulary during prototype.
summarystringRecommendedExplanation of what changed.Missing summary may warn.
statusstringRequiredRevision state such as current or superseded.Non-empty.
revisedAtdatetime stringFuture recommendedWhen the revision occurred.Prefer ISO 8601.
revisedByidentity IDFuture recommendedAuthenticated creator or reviewer.Will reference a backend identity record.
Example revision 
{
  "revisionId": "revision-oleary-story-review",
  "objectType": "historical-narrative",
  "objectId": "concept-oleary-cow-myth",
  "revisionType": "interpretation-update",
  "summary": "Marks the cow-and-lantern story as disputed rather than established fact.",
  "status": "current"
}

Staged Record

A staged record is the browser-local integrity snapshot created after a bundle passes validation. It is stored under sourceroot-staged-bundles-v1, keyed by bundle ID.

Field Type Requirement Meaning
bundleIdstringRequiredBundle identity and storage-map key.
sourcestringRecommendedOriginal path, upload, registry route, or embedded-package.
stagedAtdatetimeRequiredWhen the original staging snapshot was created.
statusstringRequiredValidation readiness at staging.
warningCountnumberRecommendedWarnings present when staged.
countsobjectRequiredCounts for nodes, assertions, edges, sources, and revisions.
bundleHash64-character stringRequiredSHA-256 of JSON.stringify(bundle).
embeddedBundleImport BundleRestored packages onlySelf-contained bundle used without the original JSON file.
importedAtdatetimeRestored packages onlyWhen an inspected package was restored.
integrityStatusstringRestored packages onlyCurrent snapshot state, currently current.
restoredBystringOptionalPrototype reviewer label; future authenticated identity.
Example staged record 
{
  "bundleId": "historyroot-fire-events-v2",
  "source": "data/historyroot-fire-events-sourceroot-import.json",
  "stagedAt": "2026-07-16T20:30:00.000Z",
  "status": "ready",
  "warningCount": 0,
  "counts": {
    "nodes": 11,
    "assertions": 13,
    "edges": 11,
    "sources": 11,
    "revisions": 2
  },
  "bundleHash": "64-character-sha256-value"
}

Self-Contained Staged Package

A package combines the staged integrity record and the complete bundle into one portable JSON artifact.

exportType: sourceroot-staged-package exportVersion: 1.0.0
Field Type Requirement Meaning
exportTypeliteralRequiredMust equal sourceroot-staged-package.
exportVersionliteralRequiredCurrently 1.0.0.
exportedAtdatetimeRequired on exportWhen the file was created.
packageIdstringRequired on export{bundleId}:{first16CharactersOfHash}.
recordStaged RecordRequiredStored integrity snapshot.
bundleImport BundleRequiredComplete embedded knowledge bundle.
Package shape 
{
  "exportType": "sourceroot-staged-package",
  "exportVersion": "1.0.0",
  "exportedAt": "2026-07-16T21:00:00.000Z",
  "packageId": "historyroot-fire-events-v2:0123456789abcdef",
  "record": {},
  "bundle": {}
}
Package integrity is content integrity, not identity authentication. SHA-256 proves whether the bundle changed relative to the staged record; it does not prove who created or approved the package.

Versioning and Migration Policy

This is the recommended policy to adopt before backend persistence. Package exports already enforce exact version 1.0.0; formal bundle migrations are not yet implemented.
Major version
Breaking field, meaning, identity, or package-shape change.
Minor version
Backward-compatible optional fields, extension collections, or new enum values.
Patch version
Documentation, validation bug fixes, or clarifications that do not change stored meaning.

Required migration rules before backend launch

Read old version
→
Identify migration path
Preserve original artifact
→
Create migrated copy
Record migration event
→
Link old and new hashes
Revalidate migrated content
→
Allow or block persistence

Future Backend Mapping

These mappings are a planning guide, not a final database design. They show how the current browser contract can move into persistent storage without discarding the working model.

Nodenodes table and /nodes APIStable IDs, domain ownership, metadata JSON.
Assertionassertions tableForeign key to node; many-to-many source links.
Edgeedges tableTwo node foreign keys; relationship indexes.
Sourcesources tableDeduplication, canonical URLs, review metadata.
Revisionrevisions or append-only event tablePrefer immutable audit records.
Import Bundlebundles plus object membership tablesStore original JSON, calculated hash, validation result, and schema version.
Staged Recordbundle_snapshotsReplace browser-local map with durable snapshot rows.
Packagepackages or object storagePreserve exact exported artifact bytes and hash.
Inspection Recordpackage_inspectionsAuthenticated reviewer, decision, issues, timestamp.
HistoryRoot extensionsDedicated extension tables or versioned JSONBKeep core API stable while domain models evolve.
